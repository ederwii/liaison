# liaison Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public repo (`ederwii/liaison`) a developer clones, runs `./setup` in, opens Claude Code in, and gets a Slack-reachable coordinator session with handoffs, subagents, a release flow, and an optional advanced mode with tmux peers.

**Architecture:** Three layers in one repo. (1) `bridge/`: the existing Slack daemon and verbs (TypeScript on Bun), trimmed to Slack-only and renamed. (2) `bin/liaison` + `setup`: bash, engine-free, owning install state under `.liaison/` and `~/.liaison/`. (3) `engines/claude/` + `skills/` + `hooks/`: the only Claude-specific code: project-level `CLAUDE.md`, settings, skills and the context-guard hook.

**Tech Stack:** Bun 1.x + TypeScript (bridge, `bun test`), bash 3.2-compatible scripts (macOS stock bash), Python 3 (hook), tmux (advanced). No other runtime.

**Spec:** `docs/superpowers/specs/2026-10-25-liaison-design.md`

## Global Constraints

- All code, comments, docs, skills and bot copy in **English**. The owner's language is a runtime setting (`.liaison/config.json` → `language`), used only in what the session/bot says to the owner.
- **Zero** occurrences of the source's names, absolute home paths, data directory and env prefix anywhere in the repo (the exact pattern lives in `scripts/audit-leaks.sh`) (LICENSE and `git log` authorship excepted). `scripts/audit-leaks.sh` enforces it and runs in `tests/run`.
- Secrets only in `~/.liaison/.env` (mode 600). Never in the repo, examples, tests, logs or test fixtures (fixtures use `xoxb-fake…`/`xapp-fake…`).
- Scripts run on **bash 3.2** (no associative arrays, no `mapfile`, no `${var,,}`, no `declare -A`). `tests/run` executes every bash test with `/bin/bash` on macOS.
- macOS and Linux. Platform branches only in: autostart service, `sed -i`, `realpath`, `stat`.
- `./setup` and every `liaison` subcommand are idempotent: a second run changes nothing and says so.
- Setup never writes into a registered project's folder. Only `~/.liaison/`, `~/.local/bin/` symlinks (after a yes), the shell rc (after a yes), and the office's `.liaison/` + `.claude/`.
- Nothing installed is tracked by git: `.liaison/`, `.claude/skills/`, `.claude/settings.local.json`, `projects/` are git-ignored.
- No GitHub Actions workflows. All tests local: `tests/run` exits non-zero on any failure.
- Commit per task with the attribution trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. Re-running `./setup` on a finished install prints "nothing to do" and leaves `~/.liaison/.env` untouched (Task 4 test `setup_rerun_is_noop`).
2. Tokens pasted with trailing newline or spaces are trimmed; a bot token not starting with `xoxb-` or app token not starting with `xapp-` is refused with exit 2 before anything is written (Task 4 test `setup_rejects_bad_tokens`).
3. `slack-say` from a folder that is not registered posts to the office channel; it never auto-creates a channel named after the folder (Task 2 test `unregistered folder routes to office channel`).
4. The context-guard hook is a no-op for a session that did not run `liaison guard register`, so a contributor opening the office folder is never blocked (Task 6 test `test_unregistered_session_is_noop`).
5. A `~/.local/bin` that is not on PATH: `setup` warns with the exact line to add and `liaison status` shows `path: not on PATH` instead of pretending (Task 4 test `setup_warns_when_local_bin_not_on_path`).
